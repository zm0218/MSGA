# MSGA

**销售文档可执行性诊断 Skill：让销售知道标准、路径、前提，以及卡住时找谁。**

[English](README.en.md) · [完整 Skill](SKILL.md) · [示例与验收场景](EXAMPLES.md) · [MIT License](LICENSE)

MSGA 用于审阅销售培训、SOP、行动指南、业务方案和政策说明，也可在生成这些文档时做交付前检查。它适用于各行业，不预设公司组织、产品或销售模式。

## 检查什么

| 维度 | 核心问题 |
| --- | --- |
| 概念与动作标准 | 核心概念是否清楚？谁做什么，做到什么程度，凭什么判断完成？ |
| 流程与路径 | 能否从当前状态走到目标？分支、交接、异常和结束条件是否清楚？ |
| 前提与依赖 | 客户、资源、权限、人员及前序工作等必要条件有没有被点明？ |
| 求助与支持 | 遇到问题找谁、走什么入口、提交什么信息、无响应时怎么办？ |

例如，“筛选优质客户，积极推动试用，成功后转合作，有问题找总部”看似有步骤，却没有资格标准、成功条件、申请入口和具体求助路径。MSGA 会定位这些缺口，并提供可插入原文的修改建议。

## 输出什么

1. 总体判断与审阅范围。
2. 四项核查概览：满足、部分满足、缺失、待确认或不适用。
3. 按影响排序的问题：阻断执行、优先补齐、表达优化。
4. 原文依据、具体位置、执行影响及建议替换文字。
5. 待确认事项与修订后的验收条件。

没有依据的负责人、阈值、渠道或服务承诺会标为 `【待确认：具体事项】`，不会伪装成现行规则。文档没写某项支持，不代表公司没有该支持。短通知按自身用途检查，不强求扩成完整销售手册。

## 快速使用

### 不安装，直接试用

在支持文件或长文本输入的 AI 对话中提供 [SKILL.md](SKILL.md)，要求按其规则审阅，然后上传、粘贴或指定待审文档。文件格式读取能力取决于所用 AI 工具。

```text
请按 MSGA 的规则检查下面这份面向销售的文档，给出完整诊断和修改建议。
```

### 安装到 Codex

以下命令适用于 macOS / Linux，要求已安装 Git；如果目标目录已存在，请先备份旧版。

```bash
git clone https://github.com/zm0218/MSGA.git "${CODEX_HOME:-$HOME/.codex}/skills/msga"
```

在新任务中调用：

```text
请用 $msga 检查这份销售操作文档，给出原文依据、问题优先级和可直接采用的修改建议。
```

也可下载仓库 ZIP，将包含 `SKILL.md` 和 `agents/` 的目录命名为 `msga`，放入技能目录。

### 其他 Agent 工具

核心规则是 Markdown，不依赖专有 API 或 Python/Node 运行环境。将 `SKILL.md` 放入宿主支持的技能目录，或作为审阅指令提供；调用语法、文件读取和自动选用行为由宿主决定。`agents/openai.yaml` 是 Codex 的界面元数据，其他工具可以忽略。

## 自动检查的范围

已启用按任务语义选用。宿主识别到正在编写或审阅销售文档时，可以加载 MSGA；显式使用 `$msga` 可清楚表达调用意图。

MSGA 不监控磁盘、不自动扫描同事文件，也不保证每次对话都会自动触发。需要在当前任务中提供或指定材料。仅要求诊断时不覆盖原文件；要求修改时按授权范围处理。

当前规则与默认报告语言为中文，可在请求中指定其他输出语言。中文版 `SKILL.md` 是规则的唯一来源，英文 README 是使用说明。

## 验证状态

初版已进行 Skill 格式检查、Codex 技能发现检查及三类示例走查。示例走查由编写助手执行，尚无独立模型基准测试、真实销售用户测试或效果统计。文档诊断不等于公司审批或实际业务效果证明。

## 反馈与贡献

通过仓库 Issues 提交问题或建议，通过 Pull Request 提交改进。反馈时请说明文档用途、预期判断、实际判断及最小复现材料；仅提交你有权公开的脱敏示例，不上传真实客户信息、内部报价、凭据或未公开制度。

新增规则应能解释它解决的实际执行问题，并尽量配一个“应该发现问题”和一个“不应误报”的例子。
